# Road restriction, road segment and ferry service data sources

Research for the Open Touring and Waypoint Database (OTWD). Retrieved 2026-10-16. Every claim carries a URL to the primary source. "Unverified" marks anything I could not confirm from the publisher's own page or API. Counts were taken live from the publishers' services on the retrieval date.

OTWD publishes under CC BY 4.0, so a source is usable only under CC BY 3.0 AU, CC BY 4.0, CC0, or explicit written permission. ODbL and OpenStreetMap-derived data are excluded.

## 1. Headline findings

1. Victoria has strong open data for all three record types. The best single source is Vicmap Transport (CC BY 4.0), which carries `height_limit`, `load_limit`, surface, vehicular access class, seasonal dates and ferry route lines. Source: [Vicmap Transport REST API record](https://discover.data.vic.gov.au/api/3/action/package_show?id=vicmap-transport-rest-api) and the live [FeatureServer](https://services-ap1.arcgis.com/P744lA0wf4LlBZ84/ArcGIS/rest/services/Vicmap_Transport/FeatureServer).
2. The best Victorian clearance dataset (VicRoads "Structure Height Clearance", 1,237 points with per-direction clearances) has been delisted from the data.vic.gov.au catalogue. Its licence is now unconfirmed. See section 3.1.
3. The NHVR National Network Map is built on OpenStreetMap and states no reuse licence. It is not usable. See section 2.1.
4. No source anywhere supplies a "towing permitted" flag, and no Victorian operator publishes ferry vehicle limits as open data. Contributors must fill both.
5. Several state sources record clearance as a single minimum number. Others separate signed from surveyed values, or record per direction or per lane. The data model must hold all of these. See section 8.

data.gov.au is a harvest aggregator. Licence fields are often "notspecified" even when the publisher states one. Always cite the publisher's record, as done for each dataset below. Catalogue API: [data.gov.au CKAN](https://data.gov.au/data/api/3/action/package_search).

The data comes through as numeric codes defined in separate VMREFTAB tables ([Road Seal Table](https://discover.data.vic.gov.au/dataset/vicmap-reference-transport-road-seal-table), [Road Restrictions Table](https://discover.data.vic.gov.au/dataset/vicmap-reference-transport-road-restrictions-table), [Vehicular Access Table](https://discover.data.vic.gov.au/dataset/vicmap-reference-transport-road-vehicular-access-table)). ## 8. Data model implications

1. **Clearance has several meanings.** Sources differ on what the number represents.
   - Signed: Brisbane records `signed_clearance_min` and `signed_clearance_max` with a `validation_date` ([Brisbane API](https://data.brisbane.qld.gov.au/api/explore/v2.1/catalog/datasets/road-restrictions)). Tasmania says the signposted clearance "is the correct legal clearance and takes precedence" ([record](https://data.gov.au/data/dataset/height-clearance-under-overhead-structures)).
   - Surveyed: WA links each Drive Under Structure to a survey certificate ([layer 781](https://gisservices.mainroads.wa.gov.au/arcgis/rest/services/OpenData/HVS_Networks_DataPortal/MapServer/781)).
   - Unspecified: Victoria and NSW do not say, and Victoria warns clearance "should not be relied upon to be 100% correct" ([Wayback](http://web.archive.org/web/20250323075804/https://discover.data.vic.gov.au/dataset/bridge-structures2)).
     Store `clearance_m`, `clearance_basis` (signed, surveyed, unknown), `source_date` and a `validated_on` date.
2. **Direction and lane.** Victoria holds heights per compass direction plus forward and reverse. Tasmania holds clearance for up to three lanes plus a "lane under" value. NSW holds none. The record needs an optional list of {direction or lane, clearance} entries plus an overall minimum.
3. **Structure role.** A bridge can be driven over (weight and width matter) or under (height matters). WA splits these into separate layers. Victoria's clearance data includes gantries (433 of 1,237) and signs, and the Vicmap point layer includes tunnels, fords, gates and level crossings. The Road restriction record needs a `structure_type` and a `passage` of over or under.
4. **Limit types.** Height, width, weight and length limits come from different sources and rarely appear together. Keep each as an independent optional field with its own basis and date. Vicmap `load_limit` units are unverified, so confirm tonnes before import.
5. **Temporary versus permanent versus seasonal.** The DEECA closures layer mixes flood, fire, maintenance and seasonal closures with explicit closure and reopen dates ([layer sample](https://opendata.maps.vic.gov.au/geoserver/wfs?service=WFS&version=2.0.0&request=GetFeature&typeNames=open-data-platform:paim_vm_tr_road_closures&count=2&outputFormat=application/json)). Vicmap seasonal dates carry stale years. Model seasonal closure as a recurring window (month and day, with the gazette year and an authority) and keep incident closures out of the static database or give them an expiry.
6. **Surface and access are small enumerations with local codes.** Vicmap uses numeric codes backed by reference tables. NSW uses named values including `Unsealed4WDSurface`. WA uses a Yes or No unsealed flag. Define OTWD values (sealed, unsealed, unsealed 4WD, unknown) and keep the source code in a provenance field.
7. **Ferry geometry versus service.** Route lines (Vicmap, NSW, Geoscape) and terminal points (Geoscape) carry no service rules. Ferry service rules live in operator pages. Model terminal, route and service as linked records, with vehicle classes as length bands that include the drawbar for towing.
8. **Capacity units differ.** NSW publishes cars per crossing and a tonne limit for one ferry. Operators publish length bands. Allow `capacity_cars`, `max_load_t`, and class bands independently.
9. **Provenance per field.** Because attributes mix licences and bases, record the source dataset, licence, retrieval date and attribution string on each record.
10. **Coordinates.** NSW clearance coordinates are the bridge start point, not the road under the bridge ([NSW file notes](https://opendata.transport.nsw.gov.au/data/dataset/de2efa35-95c2-484d-8259-63f56685e9ea/resource/65815d34-e4bd-456e-8707-349fcb422496/download/nsw-state-roads-vertical-clearances-october-2023.xlsx)). Store a `position_accuracy` note.
